# Запасы семьи

Вкладка «Запасы», маршруты `/stock`, `/stock/new`, `/stock/[itemId]`.

Реализовано:

- Общие запасы выбранной семьи: корм, лекарства, расходники и другое. Добавление названия, единицы, начального остатка, порога покупки и примечания.
- Единицы: г, кг, мл, л, шт, табл, упак. Значения с точностью до 3 знаков, включая ввод через запятую. Единица после создания неизменна, чтобы сохранять смысл истории.
- Пополнение и списание с обязательной причиной. Исправление остатка оформляется отдельной операцией на величину разницы.
- История: изменение, остаток после операции, причина, время в часовом поясе профиля и имя автора на момент записи. Имя сохраняется после исключения участника из семьи.
- Поиск по названию, категории, активные/пора купить/архив. Порог включительный: остаток меньше либо равен порогу. Список и история по 30 записей на страницу.
- Изменение названия, категории, примечания и порога; архивирование и восстановление без удаления истории. Параллельное изменение карточки отклоняется по версии updated_at.
- Владельцы и участники могут менять запасы; существующая роль viewer для этого блока только читает. Посторонняя семья и исключённые участники доступа не получают.
- Загрузка, ошибка с повтором, пустые состояния, запрет повторного нажатия во время запроса. Идентификатор операции сохраняется при автообновлении страницы, повторные запросы не списывают дважды.

Применена миграция `stock_items_and_atomic_movements`, исходник `db/stock-module.sql`. Пользователи напрямую только читают stock_items и stock_movements через RLS. Запись выполняется через invoker-обёртку проверенной private.stock_action. Блокировки семьи и позиции сериализуют изменение остатков с исключением участника. Списание и запись истории выполняются в одной транзакции. Отрицательный остаток, неподдерживаемая точность и нечисловые значения отклоняются. Таблицы запасов не меняют существующие данные питомцев.

Проверки: production build и TypeScript успешно; 22 автоматические проверки; `tests/stock-database.sql` успешно проверяет дробные остатки, повторные запросы, порог, архив, неизменность единицы/истории, устаревшие изменения и права. Тестовые данные откатываются. Интерфейс в браузере и два одновременных сетевых запроса не проверялись.

Security Advisor не добавил замечаний к запасам. Остались ранее описанные [закрытая таблица приглашений без RLS-политик](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) и [отключённая проверка утёкших паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

Обновление: подключено автоматическое списание кормлений через раздел «Питание» при явной связи с кормом и совпадении единиц. Подробности в `docs/feeding-workflow.md`.

Ограничения: пополнение ручное; расход можно отмечать вручную или через связанное кормление. Нет автоматического списания из лекарственных приёмов, расчёта дней до исчерпания, партий/сроков годности и уведомлений вне приложения.
