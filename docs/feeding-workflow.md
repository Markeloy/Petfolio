# Питание, кормления и расход корма

Главная → «Питание», маршруты `/pets/[petId]/nutrition`, `/new`, `/[planId]`.

- Одно расписание задаёт одно ежедневное кормление: название корма/блюда, порция, единица, время, примечание. Утро и вечер добавляются отдельными записями. Норма задаётся пользователем; приложение не рассчитывает потребности и не даёт диетических рекомендаций.
- Сумма порций на сегодня по единицам измерения, действующие расписания, будущие версии, архив и история отметок по 30 записей на страницу.
- Сегодняшние «Покормил» / «Пропущено» на карточке кормления. Сохраняются порция и название на момент отметки, автор и время. Повторный запрос, в том числе другого участника, возвращает первую отметку и не меняет её.
- Можно связать расписание с активной позицией категории «Корм» в запасах той же семьи. Единицы должны совпадать точно — автоматического пересчёта кг↔г нет.
- При «Покормил» порция списывается через существующую атомарную операцию запасов, а запись кормления сохраняется в той же транзакции. «Пропущено» ничего не списывает. При нехватке/архивировании запаса операция целиком откатывается; нужно проверить остаток по ссылке на запас.
- Изменения рациона создают новую версию с завтрашнего дня. Сегодняшняя версия заканчивается сегодня, её история остаётся. Изменение ещё не начавшейся версии архивирует её и создаёт замену на завтра. Остановка и восстановление расписания не удаляют отметки; версию с преемником восстановить нельзя.
- Кормления отображаются в общем календаре и участвуют в выборе ближайшего напоминания на главной. Сохранённые отметки заменяют план; в прошлые дни показаны только фактические отметки. Отсутствие отметки не считается пропуском.
- Расписание использует часовой пояс профиля при создании и сохраняет его. Неоднозначное время при смене часов отображается как один приём; несуществующее время не сдвигается автоматически.
- Участники и владельцы могут менять питание; существующий viewer только читает этот блок. Прямое изменение таблиц запрещено, чтение ограничено RLS текущей семьёй. Имена авторов в истории сохраняются после исключения участника.

Применена миграция `feeding_plans_logs_and_stock_consumption`, исходник `db/feeding-module.sql`. SECURITY DEFINER-логика изолирована в private с проверкой auth.uid(), прав семьи и питомца; публичная обёртка SECURITY INVOKER недоступна anon. Блокировка семьи и плана, уникальность пары «расписание + день» и транзакция с движением запасов предотвращают двойной расход. Журнал activity_log содержит операции без изменения старых кормлений.

Проверки: сборка и TypeScript успешны; 26 автоматических тестов суммарно (включая календарь/напоминания питания); `tests/feeding-database.sql` проверяет две последовательные отметки разных участников, целостность списания, пропуск, недостаток, единицы, чужую семью, даты/время, версии и архив. Тестовые записи откатываются. Браузерная проверка и одновременные запросы двух сессий не проводились.

Security Advisor не добавил замечаний к питанию. Сохраняются прежние [закрытая таблица приглашений без политик](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) и [предупреждение о проверке утёкших паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

Пока нет: разовых кормлений вне расписания, записи фактически съеденного количества/остатков в миске, пересчёта единиц, калорий, автоматического расчёта нормы и push-уведомлений. Отметка означает выдачу всей указанной порции; исправление ошибочной отметки отдельным обратным действием ещё не реализовано.
