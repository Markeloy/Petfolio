# Документы питомца

Главная → «Документы». Маршруты `/pets/[petId]/documents`, `/new`, `/[documentId]`, `/[documentId]/file`.

Реализовано в коде:

- PDF, JPG, PNG, WebP до 8 МБ; проверка сигнатуры, безопасное имя и собственный путь файла. В Storage передаются байты с определённым сервером MIME, а не MIME из имени/браузера.
- Название, категория (паспорт, анализы, заключение, назначение, страховка, другое), примечание, имя загрузившего и размер файла.
- Поиск по названию, категории, активные/архив/незавершённые, страницы по 30 записей.
- Просмотр изображений в карточке, открытие файла отдельной вкладкой, скачивание с исходным именем. Файл выдаётся через авторизованный маршрут без кеширования и публичных ссылок. Доступ проверяется при каждом запросе, включая доступ через Storage.
- Изменение карточки с проверкой версии, архивирование и восстановление. Сам файл после завершения загрузки неизменяем; новая редакция загружается отдельным документом.
- Два этапа загрузки: pending → ready. Карточка появляется в готовом списке лишь после проверки наличия объекта, его размера и MIME. Повторная отправка не создаёт дубликат. Незавершённая запись видна автору, можно проверить завершение или выбрать тот же файл через «Повторить загрузку».
- Закрытый bucket pet-documents. Чтение готовых файлов — участникам семьи, загрузка — владельцам/участникам, pending — только автору. Исключённый участник и чужая семья доступа не получают. Нельзя перезаписать готовый объект через Storage.

База: миграция `private_pet_documents_and_upload_workflow`, исходник `db/documents-module.sql`. Метаданные через RLS; прямое изменение таблицы отозвано. Проверенные private-функции обслуживают операции и Storage-политики; публичная RPC — SECURITY INVOKER. Существующие политики фото не менялись.

## Что проверено и что осталось

- Production build / TypeScript — успешно.
- 27 автоматических тестов — успешно, включая проверку сигнатур файлов.
- `tests/documents-database.sql` — успешно: повторная инициализация, отсутствие файла, завершение по метаданным, права на путь, незавершённые записи, чтение семьи, чужая семья, исключение участника, версии, архив. Все данные откатываются. Storage-метаданные в этой проверке смоделированы, реальные байты не загружались.
- Реальная передача и скачивание файла через Storage API, а также интерфейс браузера не проверены. Автоматическая проверка безопасности отклонила создание постоянных тестовых аккаунтов в рабочей базе для сетевого теста из-за неавторизованных изменений учётных записей и состава семьи. Действие не выполнено; вместо него проведён тест с полным откатом. Для полной сетевой проверки нужен изолированный тестовый проект либо отдельно разрешённые тестовые аккаунты.
- Security Advisor не добавил замечаний к документам. Остались прежние [информационное сообщение о закрытой таблице приглашений](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) и [предупреждение о проверке утёкших паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

Ограничения: без OCR, HEIC, Word-файлов, антивирусного сканирования, общего доступа по ссылке, автоматической очистки брошенных загрузок и окончательного удаления. Просмотр PDF зависит от браузера; скачивание доступно отдельно. Файл можно открыть только после входа в аккаунт с доступом к семье.
