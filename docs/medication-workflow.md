# Лекарства: текущий рабочий блок

Реализованы экран лекарства, приёмы на сегодня, «Дано» / «Пропущено», автор и время отметки, история по 30 записей на страницу и ближайший будущий приём выбранного питомца на главной. Экран обновляется при возврате в окно и раз в минуту, пока вкладка видна. После создания лекарства открывается его экран; одинаковые времена в форме не создают два расписания.

Расчёт учитывает часовой пояс расписания, ISO-дни недели (1–7), даты курса и расписания, активность курса и расписания. История хранит дозировку на момент записи. Для повторяющегося осенью местного времени создаётся один приём в первое вхождение; несуществующее при весеннем переводе часов время не сдвигается автоматически.

## База

Действующая функция `record_medication_dose` исправлена в Supabase: `ON CONFLICT` теперь указывает уникальное ограничение по имени, исключая конфликт с именами выходных параметров. Исправление уже применено; вручную выполнять SQL пользователю не нужно.

`db/functions/record_medication_dose.sql` — сохранённое определение функции для существующей базы, **не полная начальная миграция**. Оно зависит от уже созданных таблиц, ограничений, RLS и триггеров. Исходный репозиторий не содержал истории миграций.

Функция остаётся SECURITY INVOKER, использует `auth.uid()` как автора и атомарный `ON CONFLICT DO NOTHING`. RLS и приватность Storage сохранены. Аудит приёма создаётся существующим триггером базы.

## Ограничения этого блока

- Отметки подключены для расписания `daily_time`. Интервалы и «по необходимости» явно обозначены как пока недоступные.
- Редактирование курса/расписания, исправление ошибочной отметки и ручное добавление приёма задним числом — отдельные следующие задачи; история сейчас не перезаписывается.
- Push не добавлен: напоминание отображается в приложении.
- Проверка в браузере под реальным аккаунтом пользователя ещё требуется.

## Проверка пользователем

1. Открыть питомца → «Уход» → добавить лекарство с двумя разными временами на сегодня.
2. Убедиться, что видны оба приёма и правильный часовой пояс.
3. Отметить первый «Дано», второй «Пропущено».
4. Обновить страницу: отметки и история должны сохраниться, повторной кнопки у отмеченного приёма нет.
5. Вернуться на главную: там ближайший ещё не отмеченный будущий приём; переключение питомца меняет напоминание.

## Следующий шаг: выбор дней и часового пояса

В форме создания доступны дни недели (по умолчанию все) и часовой пояс с определением по устройству. Сервер проверяет календарные даты, порядок начала/окончания, время, дни и часовой пояс до записи. Требуется хотя бы одно время: создание курса без доступного сценария отметок больше не предлагается. Кнопка блокируется на время отправки; это предотвращает обычные повторные нажатия, но не заменяет серверную идемпотентность создания курса.

Проверка типов, production build и шесть тестов расчёта расписания прошли. Новых изменений схемы базы нет. Сохранение из новой формы в живую базу в этом шаге не проверено. Существующее ограничение: лекарство и расписания создаются двумя запросами; атомарное создание и сохранение введённых полей при серверной ошибке ещё требуют доработки.

## Управление курсом

На экране лекарства можно поставить активный курс на паузу, возобновить приостановленный или завершённый курс и завершить активный/приостановленный курс. Неактивный курс сразу исчезает из расчёта сегодняшних приёмов и ближайшего напоминания; сохранённая история остаётся.

Сервер принимает только состояния `active`, `paused` и `completed`, проверяет авторизацию и обновляет строку через действующие RLS-политики household. Тест в транзакции подтвердил изменение членом семьи, запись автора в `activity_log` и отсутствие доступа у постороннего аккаунта; тестовые данные откатились. Изменений схемы базы не потребовалось.
