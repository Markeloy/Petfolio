# Навигация, язык и оформление — 9 сентября 2026

Сохранены шесть карточек питомца и пять нижних вкладок. Изменения не требуют SQL или обновления базы.

## Что изменилось

- «Ещё → Настройки аккаунта → Язык и оформление»: русский / English, светлая / тёмная / системная тема. Выбор применяется кнопкой и сохраняется на год в cookies этого браузера. Это настройка устройства, не синхронизация между устройствами. Оформление и `lang` приходят в начальном HTML; системная тема реагирует на настройки ОС через CSS. Цвет браузерной панели и manifest учитывают выбор. Manifest для системной темы использует светлый стартовый цвет, поскольку ОС не передаёт предпочтение серверу.
- Переведены интерфейс разделов, формы, подписи, статусы, известные сообщения об ошибках, даты и стандартные единицы. Имена, названия, заметки, сохранённые авторские подписи и произвольные единицы пользователя остаются исходными. Значения полей в базе, статусы, часовые пояса и даты расписаний не меняются при переводе.
- Основная навигация находится в корневом layout и сохраняется при загрузке страниц, в том числе внутри разделов. Домашние карточки и вкладки предварительно загружаются в production. Next Router хранит открытые/предзагруженные страницы в памяти 30 секунд; это экспериментальная настройка `staleTimes` Next 16.3.4. Личные данные не помещаются в постоянный офлайн-кэш.
- Вкладка «Ещё» больше не загружает питомцев, вес, фотографии и напоминания. Независимые запросы главной и напоминаний выполняются параллельно. Повторные запросы контекста питомца объединяются React `cache` только внутри серверного рендера, без общего кэша пользователей.
- После действий сохраняется существующее обновление маршрутов. Открытые экраны обновляются при возвращении в приложение и раз в минуту. Изменение другой семьёй/участником может отображаться с задержкой; это не realtime. Защита записей, повторных нажатий и проверка актуального расписания остаются на сервере.

## Обоснованные слабые места UX

| Проблема в исходном интерфейсе | Последствие | Исправление |
| --- | --- | --- |
| Смена питомца доступна через свайп и маленькие точки; «Добавить» только на последнем питомце | Непонятно, как сменить питомца или добавить следующего | Явные кнопки с именами, выделение текущего; плюс всегда справа от фото. Выбор сохраняется на время вкладки браузера и проверяется по доступному списку |
| Меню размещено внутри сменяемых страниц | При ожидании теряется доступ к соседним вкладкам | Постоянное меню, индикатор перехода, скелетон основной загрузки |
| Подписи вкладок 8,5 px, карточек 10 px; контраст описаний около 3,9:1 | Мелкий и бледный текст труднее читать | 11/12 px соответственно, усиленный контраст. Проверенные пары текста и карточек в обеих темах не ниже 4,5:1 |
| Карточка ухода обещает груминг, который ещё недоступен | Ожидание не совпадает с содержимым | Подпись отражает готовый лекарственный сценарий; будущий раздел остаётся обозначен внутри ухода |
| Наблюдатель семьи подписан обычным участником с возможностью ухода | Пользователь ожидает доступных ему действий | Отдельное название роли и описание права просмотра |

Фокус клавиатуры, области нажатия, перенос длинных имён, отступ под нижнее меню и отключение анимаций при `prefers-reduced-motion` также учтены. Это проверка интерфейса по коду и измеримым свойствам, а не исследование с реальными пользователями.

## Проверки и ограничения

- Production build и TypeScript проходят.
- 40 тестов: прежние сценарии, локализация, неизменность единиц, полнота ключей перевода, стабильные значения option, контраст, серверный рендер главной с шестью карточками и пятью ссылками, сохранение пользовательского имени на русском в английском интерфейсе.
- HTTP smoke: RU/EN, три темы в начальном HTML, login/signup, 12 защищённых маршрутов, закрытый документ без авторизации, 404, manifest, service worker.
- ESLint: 0 ошибок, 3 прежних предупреждения о `<img>`.
- Визуальный браузерный прогон и измерение задержек с авторизованной живой базой не выполнены: облачный браузер отклонил локальный URL с `ERR_BLOCKED_BY_CLIENT`. Новых тестовых аккаунтов и записей в рабочей базе не создавали.

Предзагрузка работает в production. `npm run dev` компилирует маршруты по требованию и не подходит для оценки скорости готового приложения. Первый запрос, медленная сеть, истёкший кэш и обновление данных по-прежнему могут требовать ожидания; абсолютная бесшовность не обещается.

## Обновление на Windows

Остановить запущенное приложение через Ctrl+C, затем:

```powershell
cd C:\Users\coolm\Petfolio\Petfolio
git fetch origin
git merge origin/codex/-petfolio
npm.cmd ci
npm.cmd run build
npm.cmd start
```

Адрес покажет терминал (обычно `http://localhost:3000`). Для следующего обновления снова остановить сервер, обновить код и пересобрать.
