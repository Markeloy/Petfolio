# Семья и совместный уход

Маршрут `/family`, вкладка «Семья» в нижней навигации.

## Возможности

- Список участников с именами и ролями. Новые приглашения дают роль участника, который может вести уход за всеми питомцами семьи. Владелец управляет приглашениями и составом семьи.
- Создание одноразового кода: 192 бита случайности, срок 7 дней. Код показывается после создания, копируется кнопкой или вручную. В базе хранится SHA-256, код не помещается в URL и журнал действий. Отправка человеку — вручную пользователем.
- Вступление по коду в своём аккаунте. У нового пользователя есть ссылка на семью с экрана добавления первого питомца: для вступления не нужно создавать фиктивного питомца.
- Последние 20 приглашений: действующие, использованные, отменённые и истёкшие. Владелец может отменять неиспользованные. Максимум 10 действующих и 20 созданных за час на семью.
- Удаление участника, самостоятельный выход, передача управления другому участнику, переименование семьи. Для удаления, выхода и передачи есть явное подтверждение в форме.
- Последний владелец не может выйти до передачи управления. При передаче прежний владелец становится участником; его неиспользованные приглашения отменяются.
- Переключение между семьями: собственные питомцы не переносятся и не удаляются при вступлении. Главная, календарь и создание питомца используют выбранную семью. Cookie выбора проверяется по текущему членству; устаревший выбор безопасно заменяется доступной семьёй.
- При исключении доступ к записям закрывается через существующие RLS. Исторические записи ухода остаются; имя бывшего участника может перестать читаться через действующую политику профилей, и старый экран покажет резервную подпись.

## База и проверки

Применена миграция `family_invitations_and_membership_management`, исходник `db/family-module.sql`.
Привилегированные операции находятся в `private.family_action` с пустым search_path и проверкой auth.uid(). Публичная RPC-обёртка работает как SECURITY INVOKER и недоступна anon. Таблица кодов находится в private с RLS, без прямых прав пользователей. Прямое изменение состава семьи для authenticated отозвано; регистрационный триггер продолжает работать. Общая блокировка строки семьи сериализует вступления, исключения и передачу управления. Изменения записываются в activity_log без кода приглашения.

- `npm run build` — успешно, включая TypeScript и маршрут `/family`.
- `node --test tests/*.test.mjs` — 21 проверка.
- `tests/family-database.sql` — успешно: вступление, повторный запрос, права, отмена и истечение, исключение, защита последнего владельца, передача, название и журнал. Временные пользователи и записи откатываются.
- Интерфейс в браузере и одновременные запросы из двух сессий не проверялись.
- Security Advisor: информационное сообщение [RLS без политик](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) для private.family_invites ожидаемо — прямой доступ намеренно закрыт для всех пользователей, таблицу обслуживает проверенная функция. Сохраняется прежнее предупреждение [о защите от утёкших паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection); настройки Auth в этом блоке не менялись.

Не добавлены: отправка приглашений письмом, отдельная роль «только просмотр», уведомления семье. Следующий крупный раздел — запасы и расходники.
