# Проверка и доработка Petfolio — 8 сентября 2026

Это проверенная промежуточная версия основных функций, не утверждение о полной готовности всего первоначального ТЗ.

## Что изменено

- Профиль питомца: редактирование имени, вида, пола, даты рождения, породы, окраса, микрочипа, ветпаспорта, клиники, ветеринара и примечания. Проверка настоящей даты и запрет будущей даты рождения. Сохранение сравнивает версию строки, чтобы не затереть изменения семьи; введённые поля сохраняются при ошибке.
- Настройки аккаунта: имя и часовой пояс. Существующие расписания остаются в исходном часовом поясе, история не переносится. Редактируется только профиль текущего пользователя через его сессию и RLS.
- В «Ещё» появились рабочие ссылки. Колокольчик ведёт в календарь событий.
- Новое лекарство использует текущую дату и часовой пояс профиля, а не UTC-день сервера и смену часового пояса после загрузки формы.
- Исправлена очистка формы запасов после успешной операции; новый идентификатор списания создаётся только после подтверждённого сохранения.
- Закрыт внешний переход через `next` в подтверждении регистрации, включая пути `//host` и обратные слеши.
- Добавлены общие страницы ошибки и отсутствующей записи. Кнопки повторной загрузки используют `retry`, который заново получает данные в Next 16.3.
- Исправлены четыре политики фотографий: путь проверяется по `storage.objects.name`, а не по `pets.name`. Доступ остаётся ограниченным семьёй.
- Проверка лекарственной отметки перенесена также в BEFORE INSERT триггер: автор и роль, активный неархивный питомец, ежедневное расписание, день недели, границы курса, сегодняшнее каноническое время и невозможность будущего фактического приёма. Снимок дозировки и время записи задаются базой. Работает и для RPC, и для прямого Data API INSERT. При переводе часов повторяющееся время имеет один канонический момент, несуществующее время не принимается.
- Восстановлена работа ESLint: закреплена совместимая версия 9.39.5. ESLint 10 удалил API, который продолжает использовать установленный React-плагин. Это временная совместимость; при обновлении плагина следует вернуться на поддерживаемую основную версию ESLint. [Изменение API ESLint](https://eslint.org/docs/latest/use/migrate-to-10.0.0).

SQL-тесты выполнялись в локальной памяти, с настоящими функциями модулей и локальным pgcrypto. Схема Auth и Storage частично воспроизведена; тестовые аккаунты в рабочей базе не создавались. Тесты не доказывают сетевую конкуренцию: PGlite использует одно соединение. Тесты Storage проверяют права и метаданные, а не реальную передачу байтов. HTTP smoke использует локальный недоступный адрес Supabase и отсутствие сессии: авторизованные действия этим тестом не проверяются.

Облачный браузер отказался открывать localhost (`ERR_BLOCKED_BY_CLIENT`). Визуальная проверка, вход реального пользователя, сохранение новых форм через браузер и настоящая загрузка/скачивание файлов не подтверждены. Не следует обозначать их как пройденные.

## Изменения базы

Уже применены `fix_avatar_storage_path_resolution` и `validate_medication_occurrences_in_database`. SQL сохранён в `db/avatar-storage-policies.sql` и `db/medication-dose-guard.sql`. Пользователю повторно выполнять его не нужно.

Security Advisor не выявил новых замечаний. Сохраняются два прежних:

- `private.family_invites` закрыта RLS без прямых политик намеренно; доступ идёт через проверяющую функцию. [Описание проверки](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).
- Проверка скомпрометированных паролей в Auth не включена; настройка сервиса не менялась. [Настройка защиты паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

## Что ещё не завершено

Push при закрытом приложении, полноценная офлайн-работа, интервальные лекарства и «по необходимости», отдельные сценарии груминга, автоматическое списание лекарств, исправление ошибочной отметки приёма, экспорт и подписка. HEIC и фотографии с телефона требуют отдельной проверки. Визуальная полировка отложена по предпочтению пользователя. Старые документы модулей описывают состояние на момент соответствующего этапа; таблица выше — результат этой проверки.

## Просмотр на компьютере

В терминале VS Code остановить запущенный сервер сочетанием Ctrl+C и выполнить по очереди:

```powershell
cd C:\Users\coolm\Petfolio\Petfolio
git fetch origin
git merge origin/codex/-petfolio
npm.cmd ci
npm.cmd run dev
```

Открыть адрес, который покажет терминал (обычно http://localhost:3000). Если merge сообщит о локальных изменениях или конфликте, остановиться и сохранить текст ошибки; не выполнять reset/clean. Существующий файл настройки подключения к Supabase сохраняется.

Разработчику: `node --test tests/*.test.mjs` (проверено на Node 24), `npm ci --prefix tests/isolated-db`, `npm test --prefix tests/isolated-db`, `npm run build`, `node tests/http-smoke.mjs`.
